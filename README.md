# イラスト卒論：AI分類の実行基盤

20,758投稿・26,612画像参照を、独立したCodex Cloud担当が自分で予約して処理する。
GitHubは非公開。元データ・既存の人手回答は変更しない。

**ユーザーによる全画像の事前確認は完了。除外30投稿の隔離と基準の改訂を優先し、本番・追加100投稿は停止。**
旧v2で100投稿のCloudパイロットは完了した。現在のv3は改訂した準備コードであり、まだ実画像を新仕様で再分類していない。確認完了と起動許可は別。

- `data/catalog.json`: 固定入力台帳。416バッチ、通常50投稿以下。画像の全SHA-256を検査済み。
- `data-v1`: 旧入力。v3担当へ渡さない。事前確認後に除外を物理的に取り除いた別Releaseを用意する。
- `pipeline/worker.py`: 自主予約、入力取得、JSON雛形、検証、保存、チェックポイント、完了。
- `pipeline/git_queue.py`: バッチ別のGitブランチで原子的に予約する。担当用常設サーバーは不要。
- `pipeline/collect.py`: JSONL、投稿・画像・キャラ・画像対応のCSV、不明率、要確認一覧へ集約する。
- `全画像の事前確認を開く.cmd`: 人間用のローカル一覧。AIへの画像送信はしない。
- `docs/WORKER.md`: 担当用の短い実行手順。
- `docs/OPERATIONS.md`: 起動前・試験・障害時の手順。
- `review/classification_redesign.md`: 元アプリの24項目を見直した理由。
- `docs/LABELING_V3.md`: 次版の判定基準。同じキャラを1件と数え、項目・選択肢を固定する。
- `review/original_vs_current_manual.md`: 元の24項目と現行準備版の対応。主題は必須、背景は描き込み、公式作品は一次創作へ含める。
- `review/terra_labeling_manual_draft.md`: 旧v2の固定済み基準。変更しない。
- `review/ai_tool_audit_v3.md`: AI側ツールの監査結果と未検証事項。

Python 3.10以降とGitのみ。APIキーによるモデル呼び出しは実装しない。
モデルの画像判断はCodex自身が行い、このCLIは入出力と整合性を担当する。

```sh
python -m unittest discover -s tests -v
python -m pipeline.worker contract
```

人手が40投稿/時なら20,758投稿で約519時間。40画像/時なら26,612画像参照で約665時間。
22,000画像を40画像/時で処理する場合は550時間。投稿と画像の単位を区別する。
旧v2は1担当約62.2投稿/時だった。v3の実効速度・精度・並列数は別に実測する。ローカルの構造テスト合格を画像判定の正解率と解釈しない。
