# Koyo opt-in single-image transport

Status: additive code and regression tests only. No real image acquired, no production run enabled, no label or claim written. Original production download/worker is unchanged.

## Why this changes actual transfer granularity

`pipeline_production.small_transfer.export_images` runs on a producer that already has the exact screened ZIP. It validates original size, archive SHA, original manifest SHA, members, image hashes, and exclusions using existing production `unpack`. It stages an unchanged `manifest.json`, `images/<sha256>.jpg` (one file per image), and pinned `index.json`. It does not upload anything or overwrite an export.

`fetch_posts` runs on the worker. Caller supplies trusted source metadata, unchanged exclusion policy, trusted exporter index SHA and an authenticated `fetch(path, maximum_bytes)` callback. It fetches original manifest, then only selected images sequentially, one callback per image. It never fetches the ZIP. A 10-image scheduling window can call this for post selections, but a post and its transitive same-hash peers stay grouped; a group may exceed 10 images. The original job boundary is unchanged.

## Integration boundary

This does not solve absence of a producer with authorized ZIP access. Source staging and private asset publication must occur on an authorized environment; do not repackage unverified data or bypass 403. This change is not wired into `ops_runtime_r5` and must not be used to impersonate Terra, replace existing claims, or mark a partial selection as a completed full job. Existing run provenance/claim rules still apply. In particular, historical unshared results remain protected.

The authenticated callback must enforce maximum bytes while streaming and return exact bytes, not text/base64 substitutes. It must not retry/fallback on 401/403. Credentials remain out of files, logs and URLs. Publishing individual assets or wiring live queues requires separate integration verification. No new credential or permission configuration is included here.

## Checkpoints and tests

Verified local images are reused after interruption. Each image is hash/size checked before atomic save. A mismatching existing checkpoint fails rather than overwriting. `selection-receipt.json` is written only when the selection is complete; this is an acquisition receipt, never a labeling result or job completion.

Run `python -m unittest -v test_koyo_small_transfer`. Eight unit tests cover individual calls, transitive same-hash closure, exclusion, pin and payload corruption, export overwrite refusal, 403 propagation, and interrupted/resumed acquisition. These test generated bytes, not real image classification or end-to-end source access.
