# 最初の分類項目と現行ルールの比較

2026-11-12。元資料は、提供された属性ラベルアプリのattr_server.pyのBUILTIN、読み取り専用DBの24質問定義、同梱の使い方・説明。こちらで作った初回の再設計案や旧Terraパイロット基準を「元マニュアル」とは扱わない。

現行はdocs/LABELING_V3.md / pipeline/contract_v3.py。2026-11-12の追加指示を反映した準備版。制作方法と主題を必須に戻し、背景を描き込みの段階へ戻した。公式作品は一次創作へ含め、混合という独立カテゴリを廃止した。まだv3の100投稿は開始せず、30投稿の隔離を優先している。

元アプリは24種類の質問（人物/動物ごとの繰返しや条件分岐あり）。現行は必須10系統（主題・画像種別・制作方法・作品形式・色・背景・髪色・ユニークなキャラ数・体の形・創作由来）と任意2系統（描写範囲・表情）。髪色は内部で12フラグに分かれ、保存単位も違うため、単なる24→12問の短縮ではない。

## 新しく加えた考え方

- 画像の種類（イラスト・写真・スクリーンショット等）を区別する。写真の実在人物をイラストのキャラ数へ混ぜない。
- 同じキャラが3コマや表情差分に出ても1人。元アプリの同梱資料ではこの数え方が明文化されておらず、途中のAI版は可視の登場回数を数えていた。
- 人型・動物型へ収まらない登場者用に「その他のキャラ」を設ける。元アプリに「全キャラを動物にする」という強制規則は確認できなかった。
- 「その他」は選択肢外だが内容は分かる場合。「判別不能」は根拠不足。対象外・未評価・取得失敗は別状態にし、0や「なし」と混ぜない。
- 投稿・画像・キャラを分けて保存する。1投稿の人気指標をコマ数や人数分の独立データとして増やさない。
- ポリシー拒否は投稿全体を即時暫定除外して次へ進み、通常ラベルとは別に記録する。

## 変更の意味

元の分類をそのまま維持した状態ではない。プロモーション、性別、年齢、実在/架空、時間帯、風景/デザイン細分類等は、曖昧さと作業量を抑える私の設計判断で外した部分を含む。卒論がこれらと人気指標の関係を調べるなら、その分析は今の出力だけではできない。

背景を「種類」に変えた当初のv3案では、「細かく描かれた背景ほど伸びるか」に答えられなかった。この変更は追加指示で取り消し、元の描き込みの段階へ戻した。主題も復帰したため、主題別の比較と人物・動物の有無の比較を分けられる。主題は画像別、人物・動物の有無はキャラ一覧から投稿単位で集計する。複数画像を同一投稿の独立した人気データとして水増ししない。

旧人手回答・旧100投稿の値を新ルールへ名称だけ変えて流用しない。元の研究変数で未復帰のものは上表の通り。新しい100投稿を始める前に、残す研究上の比較項目を確定する。
