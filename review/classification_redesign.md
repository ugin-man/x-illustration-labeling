# イラスト属性分類の見直し案

作成日: 2026-11-11 JST / 状態: アプリ実装を照合した設計案。モデルの分類精度・処理速度は未測定。

## 結論

今回のZIPには分類アプリ本体がある。`attr_server.py` が質問・分岐・保存処理、`attr_index.html` が画面、`attr.sqlite3` が対象一覧・実際の質問定義・人手回答を持つ。

既存アプリは一人ずつ手入力する用途を中心に作られている。AI処理では、画像を直接入力して構造化した回答を出し、人手確認に既存画面の仕組みを活用する構成を推奨する。ブラウザのボタンを2万投稿分クリックする工程は設けない。

原本・既存人手回答を保存したうえで、新しい定義の回答を別の領域に記録する。単に選択肢を追加して全件処理すると、測定単位、欠測、キャラクターの意味が揃わない。

Cloud向けの具体的な入出力・配布・回収構成は `cloud_labeling_architecture.md`、最初の実機確認は `cloud_capability_probe.md` にまとめた。

## 先に直すべき設計

### 1. 主題を一つ選ぶと別の属性が失われる

`attr_server.py:197` 以降と `attr_index.html:178` 以降では、「人物か動物」を選んだ場合だけ人物・動物の詳細を聞く。風景やポスターにも人物が描かれている場合、その髪色や表情を記録できない。

主題は複数の存在フラグにする。必要なら「主に何を見せているか」を別に記録し、主題によって観察可能な人物属性を省略しない。

### 2. キャラクター・生物の形・擬人化を分ける

コードと同梱説明には「全キャラクターを動物にする」という規則は見当たらない。現状は人物と動物に分かれ、動物に「架空」「擬人化」があるだけ。「全キャラを動物」は実装が強制する規則ではなく、運用上の解釈だった可能性がある。

新設する軸は、(a) 見た目の形、(b) 擬人化、(c) 描画スタイル、(d) キャラクター・作品の同定、(e) 創作の由来。人型のアニメキャラクターも人型でよい。動物型キャラクターも動物型でよい。「名前を知っているか」により形の分類を変えない。

| 例（設計を説明する仮例） | 見た目 | キャラクター同定 | 創作の由来 |
|---|---|---|---|
| 作品・キャラが根拠付きで特定できるピカチュウのファンアート | 動物型 | 特定済み | 二次創作を支持 |
| 投稿者が自作OCと明記する獣人 | 人と動物の混合 | 投稿者独自キャラとして申告 | 一次創作を支持 |
| 出所不明のデフォルメ猫 | 動物型 | 不明 | 判別不能 |
| 公式アカウントによる既存作品の公式イラスト | 画像による | 特定済みの場合あり | 公式作品。ファンアートと分ける |

既存キャラがいることだけでは、公式作品かファンアートか転載かは確定しない。作品同定と制作・投稿の関係を別に記録する。

### 3. 画像数と形式、色と完成度が混ざる

「一枚絵／漫画／複数イラスト」は両立する。4画像の漫画もある。「着色済み／途中または多少着色／線画・下書き」も、完成した白黒漫画を下書き扱いする危険がある。

画像ごとに作品形式と色の表現を記録する。画像数はデータから取得する。完成度は本文や明確な作業表示がある場合の補助項目にする。

### 4. 空欄が複数の意味を持つ

未着手、質問の分岐で非表示、線画なので髪色をスキップ、対象なし、追加質問が以前はなかった、の区別がCSVの空欄だけでは分からない。人数を判別不能にすると、その種類の個体質問がすべて省略される（`attr_server.py:202`）。

新しい回答は「値」と「状態」を分ける。状態は `observed / unknown / not_applicable / not_assessed / technical_failure`。未知を0や「なし」に変換しない。

### 5. 保存単位が投稿だけ

`results` は投稿ごと、`answers` は投稿×質問ごと（`attr_server.py:296`）。髪色が何枚目のどの人物のものかを固定する識別子がない。漫画で同じ人物が複数コマに出る場合の数え方も、同梱文書には定義されていない。

投稿・画像・描かれた対象を分けて保存する。分析ではまず「その特徴を含む投稿か」を使い、同じ投稿のいいね数を人物数分だけ独立した観測として増やさない。

### 6. 質問の変更履歴だけでは再現性が不足する

質問セット番号と履歴はあるが、現在の質問定義を読み込んで再保存・CSV出力する（`attr_server.py:430`, `586`, `757`）。版ごとの完全な定義スナップショットを保持する方式ではない。設定画面では追加が可能でも、組み込み質問の非表示は不可（`706`）。

さらに画面側の `prune()` は非表示の回答を削るため、カスタム質問を非表示にした後に過去投稿を再保存すると、最新回答から古い値が落ちうる（`attr_index.html:203`, `attr_server.py:610`）。履歴が残ることと、最新回答が保持されることは別である。現DBにはカスタム質問がないので、この経路による既存回答の消失を確認したわけではない。

本処理ではスキーマ、マニュアル、モデル、設定、入力を版とハッシュで固定し、更新は別runとして記録する。

## 24質問の改訂方針

これは既存データの機械的な読み替え表ではない。意味が変わる項目は再判定が必要。

| 既存qid / 質問 | 新しい扱い |
|---|---|
| purpose / 趣旨 | 人型・動物型・物体・風景・文字等の存在フラグ。複数可。主題は任意の別項目 |
| method / 制作方法 | デジタル・物理画材・併用・不明。見た目からの推測と投稿者の明記を区別。AI生成判定は画像だけで断定しない |
| form / 作品形式 | 画像ごとのイラスト・漫画・デザイン・混合・その他・不明。ファイル数は別 |
| promo / プロモーション | 画像内の宣伝表示、本文の宣伝表示を別に。作者の意図を推定しない |
| color / 色の状態 | フルカラー・限定色・無彩色・線のみ・混在・不明。制作途中かは別の補助項目 |
| creation / 創作の種類 | 一次創作・二次創作・公式・混在・不明を根拠付きで記録。既存作品の同定、転載申告は別項目 |
| bg / 背景 | 白紙/無地・抽象/装飾・描写された環境・混在・不明。密度は別の段階。人型以外にも適用 |
| n_persons / 人物の数 | 人型等の可視の描写数。正確/概数/不明を区別。同一キャラのユニーク数とは別 |
| n_animals / 動物の数 | 動物型等の可視の描写数。同上。獣人等は二重計上しない |
| person.gender / 性別 | 中核分析から外す候補。必要なら架空人物の視覚的表現を操作的に定義し、設定上の性別とは別。実写人物の性別を見た目で断定しない |
| person.pose / 構図 | 実際には描写範囲。顔・胸上・腰上・全身・部分・不明。姿勢やカメラ角度とは分ける |
| person.expr / 表情 | 笑顔・中立・怒り・悲しみ・驚き・その他・不明。見えない顔を中立にしない。必要なら複数可 |
| person.hair / 髪の色 | 画像で見える髪色。赤とオレンジを分離。複数色は色集合で記録。髪なし/隠れ/無彩色表現/不鮮明を区別 |
| person.age / 見た目 | 補助項目。描かれた年齢表現であり実年齢ではない。デフォルメや非人間で不明を許す |
| animal.kind / 種類 | 動物的な形と種の同定を分ける。架空・実在の区別は根拠がある範囲のみ |
| animal.style / 描かれ方 | 写実/様式化の軸と擬人化の軸を分離。同時に成立できる |
| animal.range / 描写範囲 | 人型の描写範囲と共通定義に寄せる。顔・上半身等が適用できなければ部分/対象外 |
| animal.expr / 表情 | 共通表情項目。現実の動物の顔を人間的表情へ無理に当てはめない |
| object.kind / 物体の種類 | 可視の物体カテゴリを複数可で記録。現実/架空は補助軸 |
| land.kind / 風景の種類 | 自然・街・室内等を複数可。架空かどうかは別軸 |
| land.beings / 人物または動物の有無 | 共通存在フラグから導出。いる場合は主題にかかわらず必要な属性を記録 |
| land.objects / 物体の数 | 「何を1物体とするか」が不明なため中核から外す。研究上必要な対象カテゴリの数だけ定義して追加 |
| land.time / 時間帯 | 朝夕・昼・夜・不明。朝と夕を根拠なしで分けない。画面の時間表現であり投稿時刻とは別 |
| design.kind / デザインの種類 | 文字中心・ロゴ・ポスター・模様・装飾等の複数タグ。人物や風景と共存できる |

## 推奨する優先度

まず全対象で揃える中核は、イラストの適格性、画像形式、色、背景、描かれた対象の形・数、髪色、描写範囲、表情、創作の由来と根拠状態。作品同定は由来判定に必要な範囲で扱う。

制作方法、制作段階、宣伝表示、年齢表現、性別表現、時間帯、物体詳細は補助項目。研究質問への必要性と試験結果を見て採用する。ラベルの種類を増やすだけで研究の質が上がるわけではない。

髪色などの観察可能な属性と、一次/二次のような外部情報を要する属性の品質を一つの「正解率」にまとめない。別々に誤り・未知・所要時間を評価する。

## 既存アプリから再利用できる点

- `post_id` と画像位置・ハッシュの対応は揃っている。
- 投稿ごとのトランザクション保存、履歴、バックアップ、CSV書き出しがある。
- 既存人手回答298件と除外40件は、基準調整と不一致確認の材料にできる。

ただし `first_unanswered_qno()` は最初の未回答を返すだけで担当者の確保がない（`531`）。同じサーバーを複数担当者が使うと同じ投稿を取得でき、保存は投稿IDに対して後から来た回答で更新する（`610`）。このまま並列担当者の共有キューには使わない。

AI結果は別runのJSONL等へ保存し、統括者が検証後に統合する。旧DBは人手回答の参照資料として維持する。画面の再利用や新規UIの実装は今回実施していない。
